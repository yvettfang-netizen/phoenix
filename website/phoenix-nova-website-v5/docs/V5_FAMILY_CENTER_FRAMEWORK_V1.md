## 人、申请与材料

账号是登录者；Member 是资料主体；Guardian 是经核验的监护关系。成年客户独立使用，家庭关系不自动授予访问权。Student 仅为教育域身份，成人身份申请不复用 education assessments.student_id。

同一 Member 可以拥有多个申请；目标层级、入学年份、材料版本、顾问与报告分别保存。现有 masters_* 与 /v1/masters 保持原契约，不改名冒充通用后台；本科与博士分支需分别确认服务端契约后启用。硕士分授课型和研究型，博士增加研究方向、科研成果、导师意向与资助需求。本科根据实际年龄处理监护授权。

材料添加、识别、本人确认、报告审核、报告发布是不同状态。未提供信息不视作 0；旧材料变更后对应报告需重新核验。首次咨询允许后补非必需材料，不先强制测评或付款。

## 两条长期服务流程

1. 服务完成 → 核验日期来源 → 客户确认 → 后台定时提醒 → 续办跟进 → 新版本日期与旧提醒取消。区分证件有效期、获准逗留期限、换领或预约节点。无日期不显示倒计时，不推算获批资格。
2. 成绩单 → 识别结果确认 → 分析草稿 → 专业审核 → 发布报告 → 自愿选择凤启学苑/问思 → 学习进展回到同一报告。

邮件后台未接通；页面仅预览提醒偏好与邮件内容。正式实现需邮箱核验、接收人授权、时区、幂等调度、失败重试、退信跟进、撤回授权和续办后的任务取消。提醒只含最少信息，阅读不等于续办完成。

## 本轮实现边界

同一项目中的网页、表单分支、内存演示记录、示例材料和报告、证件节点交互、提醒设置预览、服务交接示意、双语导航及页面描述。全部示例虚构；刷新重置，无真实上传、登录、OCR、AI、顾问通知、邮件、数据库迁移或业务 API 写入。

后端权限实施前不接真实客户资料。Family scope + subject relationship + consent + role 必须全部通过服务端校验；RLS/等效数据库隔离、操作审计、对象存储权限、撤回及删除都需有独立验收证据。前端示例切换不是身份验证。

## GEO 与发布

公开服务介绍提供准确标题、描述、语义正文与 FAQ；关键结论须有可核验来源。现有全站 private-review/noindex 保留。正式发布时仅公开介绍页进入 sitemap/canonical/hreflang；申请、证件与私人报告排除且必须服务端授权，不以 robots 代替保护。不得伪造服务资历、评价、政策或排名。
