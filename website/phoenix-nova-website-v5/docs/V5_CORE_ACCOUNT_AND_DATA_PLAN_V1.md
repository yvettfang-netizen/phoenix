## 0.1 最新决定：用户名认证直接实施

Founder 的“不能直接搭架用户名登录系统吗？”已确认本项目采用自有用户名/密码认证的第一阶段。无需等待短信商或完整业务 SQL；此前“必须先绑定外部身份服务才开始”的执行依赖由本节取代。

原 V5 已增加账户页面、注册、密码校验、服务器会话、退出全部设备、改密及一次性恢复码。最小 D1/SQLite 凭据存储只保存账户和认证运行记录；不建立第二套 Family、Member、Student 或客户业务档案。实现细节与测试见 [V5_USERNAME_AUTH_V1.md](./V5_USERNAME_AUTH_V1.md)。

启用开关默认为关闭。当前仅做了本地真实 Worker + D1 测试，未配置线上认证、部署或执行远端迁移。开启后无会话不能进入家庭中心；登录后仅显示本人账户状态，家庭资料尚未接入，不展示虚构家庭为客户本人资料。

稳定 `core_auth_users.id` 是这一认证主体的内部 `user_id`。后续迁入 Core 时保留该 UUID 及版本化密码哈希，不重复注册；Member 关联另行核验。需要统一其他已有真实账户时先对账，不能按姓名、手机号字符串或飞书 record_id 自动合并。

本期没有短信、邮箱验证、MFA 或真实客户资料授权。恢复码由客户保存，服务端仅存摘要；每次使用和改密后轮换并退出已有会话。以下规划中涉及验证码、MFA、家属与顾问权限的条目均为后续目标，不能据此宣称已实现。

## 1. 已确定的方向

V5 是现有统一网站与客户入口，Family OS 是其中的长期管理中枢。升学登记、Education / Identity / Wealth / Health Compass、凤启学苑和问思使用 Phoenix Core / Family OS 的同一套身份与授权记录。保留原 V5 视觉体系；认证页面在同一原网站内实现，其余业务仍按统一接入框架推进。

V5 不再单独建立客户主库。账号、家庭、成员、监护关系、授权和服务权益各自只有一个权威来源。各模块可以保留自己的专业业务记录，但必须映射共享 ID，不能复制一套客户密码或自行重新生成家庭与成员。

## 3. 飞书先用到什么程度

建议采用“同一 Core 主库 + 飞书运营工作台”。数据库技术先沿用 PRD 中的 PostgreSQL 方向，在确认 Jimson 的最新基线后定案。第一阶段使用原 V5 自有统一认证，业务关联与权限后续放在共享 Core。飞书用于团队跟进与必要数据视图。

| 职责 | 权威来源 / 建议存放位置 | 飞书可承担的部分 |
| --- | --- | --- |
| 密码、短信校验、MFA、登录会话 | 统一认证服务；密码哈希及密钥由其受控存储管理 | 不保存密码、密码哈希、验证码、恢复码或会话令牌 |
| user_id、family_id、member_id、监护及访问授权 | Core 共享身份与权限存储 | 引用稳定 ID；只展示员工职务所需信息，不编辑权限真值 |
| 证件节点、申请记录、报告版本、服务权益 | Core 业务主库 | 必要的日期、任务、状态与跟进视图；仍属个人资料，按授权开放 |
| 证件、成绩单、报告原文件 | 私有文件存储，Core 保存文件归属和版本 | 默认仅保存受控详情入口；不使用公开附件链接 |
| 提醒任务、发送结果、撤回和审计 | Core 的持久任务与审计记录 | 顾问待办、失败告警、确认记录；可按条件作为通知执行渠道 |

飞书已有表、行、列等细粒度高级权限，也提供记录 API；这足以支持运营场景。但以应用身份访问 Base 的权限，不会自动成为每一位网站客户的家庭权限。后者仍需 Core 对每次读取和修改做服务端授权。本段是对本项目接入方式的工程判断，并非声称飞书没有权限功能。参见[飞书高级权限](https://www.feishu.cn/hc/zh-CN/articles/962169212093-使用多维表格高级权限)及[飞书接口调用身份要求](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/create?lang=zh-CN)。

如果先不上完整业务主库，可以先以一个受控 Base 做内部业务台账；同一条业务记录此时以 Base 为准，并保留未来映射用的稳定业务 ID。这个阶段可验收登记、顾问跟进和受控邮件提醒。若要进一步让真实客户登录读写这些表，必须先实现统一认证、独立受控的权限/授权记录、服务端逐请求隔离、审计、备份与并发一致性验证；这不是“建表即可上线”。其工程成本不一定比直接建设最小 Core 主库更低。

本计划推荐：上半月统一认证与飞书运营先行，下半月建设 Core 的最小业务底座；不把飞书业务表变成密码库，也不为了临时方案再造一套客户账户。

## 4. 统一登录体验

| 用户动作 | 设计行为 |
| --- | --- |
| 进入网站 | 公开介绍页可直接阅读；保存私人登记、查看家庭中心时进入统一登录 |
| 首次开户 | 本期为测试用户名与密码注册、保存恢复码，只生成 user_id。正式客户开户再加入条款、联系方式验证与本人 Member 核验；不强制添加家人 |
| 日常登录 | 本期用户名 + 密码；用户名规范化并唯一。后续验证后绑定邮箱或手机号为附加方式，仍使用同一 user_id |
| 接收邮件提醒 | 单独绑定并验证提醒邮箱，选择提醒类型与接收人；手机号登录不会自动提供可用邮箱 |
| 跨模块使用 | 已验证会话在原 V5 内连续；进入已接通模块时保留同一 user_id 与经授权的成员上下文 |
| 忘记密码 | 本期使用客户保存的一次性恢复码；使用后轮换、撤销已有会话并重新登录。邮箱恢复待验证投递渠道上线；不发送原密码 |
| 更换号码或邮箱 | 近期重新认证、验证新渠道、通知旧渠道；仅掌握一个新手机号不能接管已有账号 |
| 找回所有渠道丢失的账户 | 进入人工核验工单；员工不能查看密码或仅凭姓名、证件号码及口头请求改绑 |
| 账号与安全 | 登录方式、密码、MFA、设备会话、退出所有设备、资料导出与注销申请 |

手机首轮覆盖目标为 +86、+852，并在选定供应商后实测；海外客户保留邮箱入口。没有短信和邮箱发送环境的验收证据时，对应登录方式保持未启用。

同一用户绑定更多登录方式时，必须验证当前账号和新增方式；不能根据同名、同邮箱字符串、同一联系人手机号或飞书 record_id 静默合并。家长手机号绑定家长 User，孩子作为 Member 管理。成年人自行开户后需经可追溯流程关联既有本人资料，不自动接收家长所有授权。

用户可先留下匿名测评草稿；认领时同时验证草稿凭证、登录会话、资料主体和适用授权，不能仅凭 assessment_id 认领。当前虚构 Demo 数据永不迁入真实客户档案。

## 5. 账号、资料主体与权限

以下为逻辑实体，实施时映射到现有 Core 表，不是要求新增同名的第二套表。

| 实体 | 最小职责 |
| --- | --- |
| User | 登录主体、状态、联系方式核验状态、认证服务主体映射；稳定内部 ID 不依赖手机号或邮箱 |
| AuthIdentity | `(issuer, subject)` 唯一映射 user_id；新增登录提供方不改变业务 ID |
| Family / Membership | 工作空间、成员关系、角色和有效期；primary_family_id 只控制默认展示，不是权限凭据 |
| Member / UserMemberLink | 被管理的人与其本人账号的核验关联；未成年人可无登录账号，成人不被强制挂到 Student |
| GuardianRelationship | 经核验的监护关系、适用范围和有效期；家庭管理员身份不能代替监护核验 |
| SubjectGrant / AdvisorAssignment | 指定访问者、资料主体、数据类别、操作、有效期和撤销状态 |
| Consent | 目的、数据类别、版本、同意人及其代表资格、时间、撤销时间；必要服务、提醒、顾问、AI、营销分别记录 |
| Session / Audit | 受控会话及不可由普通用户改写的事件记录；不记录密码、验证码或完整证件正文 |
| ServiceEntitlement | 服务有效期与服务范围；购买服务不能绕过资料主体授权 |

成年本科、硕士和博士客户默认管理自己。中小学及其他未成年客户按实际年龄、监护关系和适用规则分配权限。夫妻及成年子女各自授权共享；家庭组织者可以邀请和安排事务，但不因 Owner 角色读取他人的完整身份、财富或健康信息。

一人可参与多个经授权家庭；每次切换重新核验范围。学业 Student 是 Member 的教育域关联，Identity 的申请主体使用 Member / Identity Subject。学生成年或监护关系变化时，触发权限复核，暂停不再有效的代理授权。

每次请求必须同时验证：有效会话、账号状态、工作空间关系、资料主体关系、所需授权、允许操作及必要的服务权益。数据库采用 RLS 或经过验证的等效隔离；文件下载、后台任务和 API 也执行相同边界。页面隐藏、URL 中的 family_id 以及前端传入的角色都不是授权证据。

顾问仅能访问分配给自己的有效案件和允许字段。运营默认看任务及最少联系信息。技术管理员管理系统与账号状态，不默认浏览客户正文；确需临时访问时走限时审批并审计。员工内部登录可以保留飞书身份，但必须和客户入口、令牌受众及权限分开。

## 6. 认证与安全参数草案

第一阶段采用原 V5 的最小认证实现和运行时原生 scrypt，凭据进入受控认证表，具体参数见实施交接文档。密码明文、恢复码明文、会话明文不得进入业务表、飞书、代码仓库或日志。下述 MFA、泄露密码筛查、改绑及正式业务授权要求仍待实现验收。

建议统一最低密码长度 15 字符、支持至少 64 字符、允许密码管理器与粘贴、筛查弱密码及泄露密码；不强迫每月换密或机械拼凑字符种类。管理员/顾问强制多因素；客户绑定可用第二因素，查看完整敏感文件、导出、改绑或授权他人时进行近期强化认证。短信单独登录不视为多因素，重复发送短信不能充当独立第二因素。依据[NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html)与[OWASP 认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

一次性验证码暂按 5 分钟、60 秒重发间隔、单次挑战最多 5 次校验错误设计，并对账号、目标地址、IP 与系统总发送量限流。重发使前码失效；并发只允许一次消费，登录码、改绑码、找回码严格区分用途。这些是待验证的产品参数，不是已配置能力。响应不泄露账户是否存在。

Web 会话使用服务端校验的 Secure、HttpOnly、host-only Cookie，合理设置 SameSite 并保护变更请求免受 CSRF。禁止在 localStorage、URL、公开页面或日志中携带长期访问令牌。跨域模块若保留，采用成熟标准单点登录流程并校验回调白名单，禁止靠 URL 传 user_id 作为登录。受控网关身份头必须有可信来源验证，不能在普通公网部署时直接信任用户自带请求头。参见[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

初始会话参数建议：客户空闲 30 分钟、最长 12 小时；敏感操作要求 5 分钟内强化认证；员工空闲 15 分钟、最长 8 小时。长时“记住设备”后置，避免先开放永久登录。密码重设、停用或风险事件撤销会话；授权撤回须使下一次服务端访问即失效，不等待旧 JWT 到期。找回密码不能绕过已绑定 MFA，MFA 丢失使用专门恢复流程。参见[OWASP 密码找回](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

## 7. 同一主库如何与飞书协作

正式 Core 成为权威来源后，向飞书同步最小必要视图。每条映射保留 core_id、feishu_record_id、数据版本、同步时间和来源；record_id 永不替代 user_id / family_id / member_id。

顾问在飞书提交的续办日期或状态变更是变更申请，必须经服务端核验操作人、案件分配、字段白名单和期望版本后落入 Core。不得允许直接改表绕过 Member 授权。账户状态、家庭归属和 Consent 真值不作为普通员工可编辑列。发生版本冲突时退回核对，不用“最后写入覆盖一切”。

同步使用持久事件、幂等键、失败重试与对账；同一变更不能从两边反复触发循环。切换 Base 临时台账到 Core 时，先冻结写入、核对数量和归属、保存映射及备份、切换唯一写入方，再恢复；保留原业务 ID。需有独立迁移审批，本轮不执行。

## 8. 证件提醒与邮件

登录验证、账号安全通知、业务节点提醒、营销触达是四类不同目的。客户验证邮箱后选择本人或已授权成员的节点通知；成员共享关系本身不自动订阅邮件。

飞书工作流支持邮件操作，但依赖可用发送邮箱和当前配置，自动化也存在月度运行额度；额度用尽可能停止运行。因此不能把“页面开了提醒”当成送达保证。依据[飞书发送邮件说明](https://www.feishu.cn/hc/zh-CN/articles/209545872125-在工作流和自动化中发送邮件)及[工作流额度说明](https://www.feishu.cn/hc/zh-CN/articles/949255360693-多维表格工作流和自动化流程常见问题)。

在受控试点中可使用飞书邮件执行步骤，须有企业管理的发送账号、明确收件人授权、额度监控、测试邮箱、失败/退信跟进与人工兜底。正式系统由 Core 持久记录计划、领取任务、幂等键、发送请求和结果；发送方调用前再次检查授权与当前日期版本，重试不能造成多次提醒。

签证获准逗留期限、证件有效期、换领/预约节点分别管理，不给所有身份证套同一种到期规则。日期来源待核验时不制造倒计时。续办后保留历史并取消旧任务；撤回接收授权后取消待发任务。邮件只含必要提示与需登录的详情入口，不附完整证件或成绩单。定期提前提醒的天数由客户服务规则确认后配置。
