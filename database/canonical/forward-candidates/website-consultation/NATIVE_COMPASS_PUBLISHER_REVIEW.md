## Education SQL publication contract

Load formal 0001–0037, the #116 intake and event candidates, then #74 and the optional `education-native-publisher.sql` only in an isolated fixture. Both optional files require review before any environment adoption. The compatibility workflow hashes the #74 source and runs both PostgreSQL versions against the exact #116 head.

The backend publisher is `crm.publish_education_compass_completion(event, lead, contract, assessment)`. It requires the dedicated NOLOGIN capability on the service LOGIN, the LOGIN-bound 0036 acquisition contract, a live Family context and a verified Client linked to the same family. It resolves the subject from the native sealed row and calls `crm.record_compass_event()`. There is no public browser endpoint. The candidate records the minimum ID reference, not answers, result, report or payment. A submitted assessment is distinct from a published or paid report.

The candidate uses a separate `EDUCATION_COMPASS_CRM_REFERENCE / EDUCATION` grant on the exact student and authorized acting recipient. Case consent or native assessment consent alone is insufficient. The fixture seeds only the synthetic sharing grant and uses the existing authorized withdrawal API. Approved sharing text, collection, audit receipts and one coordinated real source-to-CRM runner are pending. The source's native access predicate and the independent sharing grant are rechecked for each read and retry. Default-deny also applies to old stored references whose source cannot be verified.
