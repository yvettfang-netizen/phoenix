`consent.compass_reference_grants` extends the existing Canonical Consent schema for exact assessment scope. Source processing Consent, `IDENTITY_CASE`, generic Family membership and staff intake rights convey no sharing rights. Reads recheck native authority and the exact share grant. Withdrawals are append-preserving state changes with a minimal audit decision. A withdrawn receipt is never restored by retry. The signer can withdraw an existing receipt after losing native source access, provided their authenticated Family context remains valid. Operational withdrawal after loss of the whole account needs a separately approved privacy workflow.

## Runtime wiring and enterprise permission proof

- Load formal 0001–0037, `intake.sql`, `compass-events.sql`, `native-compass-consent.sql`, then `identity-native-authority.sql` or the pinned #74 source followed by `education-native-publisher.sql`. The optional Education and Identity hooks do not overwrite each other.
- `native-compass-service.mjs` is an internal server module. Use distinct authorization binder and operation pools with the existing Canonical family-session resolver. Bind via 0023/0025 database ticket resolution and consume the one-time ticket before the operation. Check session currency again after asynchronous calls. Clear and discard the connection, destroying a suspect checkout. No public route is mounted. Host middleware must bind the acknowledged notice and source action to its authenticated, CSRF-protected server request. Configure code with protected settings in Staging only after the approvals are recorded.
- Education and Identity publisher actors have dedicated LOGIN roles with only their domain's NOLOGIN capability. The Identity submission writer has a separate NOLOGIN capability and cannot publish. The operator-only registrar reuses `crm.acquisition_contract_revisions`, binds the exact source and LOGIN, and accepts neither a broad Canonical App member nor a migration/backup account. Ordinary App roles retain no ability to publish native assessments. Native assessment metadata tables are direct-access denied. No publisher is granted raw answers or access to another domain.
- Existing staff integration still resolves a verified issuer/subject and maps it to an active Canonical Principal. Dispatcher and Adviser access remains restricted by organization, business domain and assignment. Founder remains a default-HOLD minimal read-only projection, with no SQL bypass or assessment export. Family OS continues to require the active Family and object-specific source authorization. Credentials, formal IdP enrollment and controlled Staging evidence remain environment work; code and synthetic fixtures are part of this PR.

The [prior source decision](NATIVE_COMPASS_PUBLISHER_REVIEW.md) describes the Phase 1 baseline. This document supersedes its single-domain share implementation and Identity denial while the optional Identity source is installed. Base CRM-only installation remains deny-by-default for native references.
